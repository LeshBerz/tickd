# Разработка

## Требования

- **Node.js 22.22 или новее** — версия зафиксирована в `package.json` (`engines`).
- npm (проект использует `package-lock.json`).
- Браузер с поддержкой `localStorage` и CSS `@theme` (современные Chrome, Edge, Firefox,
  Safari).

## Установка и запуск

```bash
npm ci        # установка строго по lock-файлу
npm run dev   # dev-сервер Vite с горячей перезагрузкой
```

Приложение открывается на `http://localhost:5173`. Проверка типов и линтер в dev-режиме
не запускаются — для них есть отдельные команды.

## Скрипты

| Команда              | Что делает                                              |
| -------------------- | ------------------------------------------------------- |
| `npm run dev`        | Dev-сервер Vite                                         |
| `npm run build`      | `tsc -b` (проверка типов) и production-сборка в `dist/` |
| `npm run preview`    | Локальный просмотр собранной версии                     |
| `npm run lint`       | Biome: линтер, форматирование, порядок импортов         |
| `npm run format`     | Biome с автоисправлением                                |
| `npm run typecheck`  | Только проверка типов (`tsc -b`, без эмита)             |
| `npm test`           | Unit-тесты (Vitest, один прогон)                        |
| `npm run test:watch` | Unit-тесты в режиме наблюдения                          |
| `npm run test:e2e`   | E2E-тесты Playwright                                    |

E2E-конфигурация сама собирает приложение и поднимает `vite preview` на порту 4173,
поэтому отдельная сборка перед `npm run test:e2e` не нужна. При первом запуске
понадобятся браузеры Playwright:

```bash
npx playwright install chromium
```

## Сборка и базовый путь

Обычная сборка рассчитана на корень домена:

```bash
npm run build
```

Для хостинга в подпути (GitHub Pages раздаёт проект по `/<репозиторий>/`) сборка получает
базовый путь через переменную окружения:

```bash
BASE_PATH=/tickd/ npm run build   # macOS / Linux
$env:BASE_PATH="/tickd/"; npm run build   # PowerShell
```

`base` в `vite.config.ts` читается из `BASE_PATH` и по умолчанию равен `/`. Роутер берёт
`basename` из `import.meta.env.BASE_URL`, поэтому имя репозитория нигде не зашито в код:
достаточно передать путь при сборке. Не меняйте одно без другого — это единственный
источник истины ([ADR 0004](adr/0004-routing-on-github-pages.md)).

## Публикация на GitHub Pages

Workflow [`.github/workflows/deploy-pages.yml`](../.github/workflows/deploy-pages.yml)
запускается на push в `main` (и вручную из вкладки Actions):

1. ставит зависимости по lock-файлу;
2. прогоняет линтер, проверку типов, unit-тесты и сборку с `BASE_PATH`;
3. добавляет `404.html` для глубоких ссылок;
4. публикует `dist/` через GitHub Actions.

Что требуется от владельца репозитория один раз:

1. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
2. Убедиться, что ветка по умолчанию — `main` (workflow реагирует именно на неё).
3. После первого успешного запуска сайт будет доступен по адресу
   `https://leshberz.github.io/tickd/`.

Сам деплой из чата не выполняется: публикация — отдельное решение владельца.

### Глубокие ссылки и `404.html`

В GitHub Pages нет серверных перезаписей: запрос `/tickd/active` вернёт 404. Чтобы глубокая
ссылка всё равно открывала нужный экран, workflow копирует собранный `index.html`
в `dist/404.html`. Документ самодостаточен — ссылки на ассеты в нём абсолютные, а роутер
знает свой `basename`, — поэтому приложение отрисовывает тот маршрут, который запросили.
Ответ при этом остаётся с HTTP-статусом 404, что для клиентского приложения без требований
к SEO приемлемо.

Это осознанное уточнение [ADR 0004](adr/0004-routing-on-github-pages.md), зафиксированное
в [ADR 0009](adr/0009-deep-links-fallback-via-index-copy.md): предложенный там вариант
с inline-скриптом восстановления адреса несовместим с CSP из
[ADR 0007](adr/0007-input-validation-and-security.md). Статический `public/404.html`
не нужен — файл создаётся только в артефакте сборки.

## Структура проекта

```
src/
├─ app/              # store, слушатели, роутер, layout, горячие клавиши
├─ features/
│  ├─ tasks/         # slice, селекторы, схемы, хранение, компоненты списка
│  ├─ preferences/   # тема, акцент, язык, подсказки, настройки
│  └─ guide/         # шаги знакомства, геометрия, состояние
├─ i18n/             # словари en/ru и инициализация i18next
├─ test/             # помощники для рендера в тестах
├─ index.css         # токены Tailwind v4, темы, акценты, анимации
└─ main.tsx          # точка входа
e2e/                 # Playwright: сценарии, доступность, адаптивность
docs/                # документация и ADR
design/              # статический прототип интерфейса
public/              # favicon и скрипт применения темы до первого рендера
```

Правила размещения:

- Доменная логика — в `features/<feature>/`, рядом с ней тесты (`*.test.ts(x)`).
- Новый компонент не заводится в общей папке «на вырост»: общий код появляется только
  при втором реальном использовании.
- Производные данные считаются селекторами, а не в теле компонента.
- Руководство по стилю кода задаёт Biome (`biome.json`): отступ 2 пробела, ширина строки
  100, двойные кавычки, сортировка импортов.

## Требования к коду

- TypeScript в строгом режиме, включая `noUncheckedIndexedAccess` и
  `exactOptionalPropertyTypes`; `any` не используется — внешние данные сужаются через
  Valibot.
- React Compiler включён: `useMemo`, `useCallback` и `memo` по умолчанию не добавляются.
  Исключение — селекторы, создающие новые объекты.
- Стилизация — утилиты Tailwind и токены темы; жёстко заданных цветов в компонентах нет.
- Пользовательский текст не попадает в разметку как HTML;
  `security/noDangerouslySetInnerHtml` включён в Biome на уровне ошибки.
- Все новые тексты добавляются в оба словаря (`src/i18n/en.ts`, `src/i18n/ru.ts`):
  тест словарей проверяет совпадение ключей.

## Тесты

```bash
npm run lint
npm run typecheck
npm test
npm run test:e2e
```

- Unit-тесты проверяют редьюсеры, селекторы, схемы и миграции, хранение, разбор маршрутов
  и геометрию гида. Хранилище и таймеры изолируются в каждом тесте.
- E2E-тесты проверяют сценарии в настоящем браузере: добавление, фильтры, переименование,
  отмену удаления, заметки, настройки, знакомство, глубокие ссылки, доступность (axe),
  адаптивность и отсутствие горизонтальной прокрутки.
- Обязательные краевые случаи: пустой и пробельный ввод, повреждённые и устаревшие данные
  в хранилище, неизвестный маршрут.

## Полезные детали

- **Хранилище.** Ключи `tickd:tasks` и `tickd:preferences` независимы. Чтобы посмотреть
  или заполнить состояние вручную, используйте DevTools → Application → Local Storage;
  формат описан в [архитектуре](architecture.md#хранение-данных).
- **Тема до первого рендера.** `public/theme-boot.js` — обычный внешний скрипт, потому что
  CSP запрещает inline-скрипты. Если меняете формат настроек, обновите и его.
- **Контраст акцентов.** Палитры в `src/index.css` проверяются тестом
  `src/features/preferences/palettes.test.ts`; менять цвет в одиночку нельзя.
- **Прототип.** `design/prototype.html` — исходный визуальный ориентир. Он не участвует
  в сборке и исключён из проверок Biome.
- **Скриншоты документации.** Изображения в `docs/images/` сняты с собранного приложения
  в Chromium. При заметном изменении интерфейса их стоит переснять в размерах
  1440×900 (десктоп) и 390×844 (телефон), в светлой и тёмной теме.

## Диагностика

| Симптом                                | Причина и решение                                                              |
| -------------------------------------- | ------------------------------------------------------------------------------ |
| Порт 4173 занят при `npm run test:e2e` | Остановите предыдущий `npm run preview`                                        |
| Пустой список после перезагрузки       | Браузер блокирует `localStorage` (приватный режим) — приложение покажет баннер |
| Страница пустая после публикации       | Не включён источник Pages «GitHub Actions» или сборка шла без `BASE_PATH`      |
| Глубокая ссылка даёт 404               | В артефакте нет `404.html` — проверьте шаг сборки в workflow                   |

# 0005. Biome вместо ESLint и Prettier

- Статус: Принято
- Дата: 2026-11-02

## Контекст

- Проекту нужны линтинг, форматирование и сортировка импортов: быстро и с минимальной конфигурацией.
- Используется TypeScript 7.0 (нативный компилятор). Его npm-пакет больше не предоставляет классический JavaScript API компилятора, на который опирается typescript-eslint для type-aware правил.

## Решение

- Использовать Biome 2.6 как единый инструмент для линтинга, форматирования и организации импортов.
- `npm run lint` запускает `biome check .`.
- `npm run format` запускает `biome check --write .`.
- Включить рекомендуемый набор правил (в него входят a11y-правила) и домены `react` и `test`.
- Конфигурация находится в `biome.json`.

## Рассмотренные альтернативы

- **ESLint + typescript-eslint + Prettier.** Крупнейшая экосистема правил, включая type-aware правила и `eslint-plugin-react-compiler` / `react-hooks`. Отклонено: три инструмента и несколько плагинов, которые нужно настраивать и поддерживать совместимыми, более медленные запуски, а type-aware линтинг потребовал бы второй установки TypeScript рядом с TypeScript 7.
- **oxlint + Prettier.** Быстрый линтинг, но всё равно два инструмента для настройки и запуска.

## Последствия

- Плюс: одна зависимость, один файл конфигурации.
- Плюс: очень быстрые проверки в CI и в редакторе.
- Минус: правил меньше, чем в экосистеме ESLint.
- Минус: нет type-aware правил линтера. Типобезопасность вместо этого обеспечивает `tsc` в строгом режиме.
- Минус: часть React-специфичных правил (например, rules of hooks, значимых для компилятора) приходит из собственных реализаций Biome и может отличаться от плагинов ESLint.

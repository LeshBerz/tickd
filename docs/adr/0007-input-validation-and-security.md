# 0007. Ограничение заголовка, сбои localStorage и CSP

- Статус: Принято
- Дата: 2026-11-03

## Контекст

- Заголовок — свободный текст. Без верхней границы длинная строка ломает вёрстку и раздувает запись в localStorage.
- HTML `maxLength`, `String.length` и `v.maxLength` считают кодовые единицы UTF-16. Символ вне BMP (суррогатная пара) занимает 2; составная последовательность эмодзи — больше. Лимит во всех слоях должен использовать одну единицу.
- Ограничение только в поле обходится прямым `dispatch(add(...))` и ручной правкой хранилища.
- Вставка из буфера часто содержит переводы строк. Заголовок остаётся одной строкой. Ручной ввод по-прежнему лишь обрезает края при отправке.
- ADR 0003 загружает список по правилу «всё или ничего» и глушит ошибку записи. Пользователь не видит отброшенный список, исчерпанную квоту и недоступное хранилище (приватный режим, блокировка).
- Отдельный ключ пробы на заполненном хранилище может не записаться, хотя перезапись значения того же размера ещё проходит. Прочитанные задачи из-за этого терять нельзя.
- Приложение раздаётся статикой с GitHub Pages (ADR 0004). Заголовки ответа задать нельзя, поэтому CSP доставляется через `<meta http-equiv>`.
- Заголовок показывается как текст. Строка из хранилища не должна исполняться как HTML.

## Решение

Длина:

- `TITLE_MAX_LENGTH = 200` в `src/features/tasks/title.ts`. Это `String.length` (UTF-16) и единственный источник лимита.
- В `TaskForm` у поля `maxLength={TITLE_MAX_LENGTH}`. Счётчик `{n} / 200` виден при `n > 0`, с `aria-hidden="true"`. При `n === 200` используется `text-danger`, иначе `text-text-muted`. Отдельной ошибки «слишком длинный» нет: поле не принимает больше 200.
- `add.prepare` делает только `title.trim()` и длину не режет. Reducer не добавляет задачу, если `title.trim() === ""` или `title.length > TITLE_MAX_LENGTH`.
- В `TaskSchema` заголовок — `v.pipe(v.string(), v.trim(), v.nonEmpty(), v.maxLength(TITLE_MAX_LENGTH))`. Длина больше 200 после `trim` делает весь документ невалидным (ADR 0003).

Вставка:

- Только обработчик `onPaste`: `preventDefault`, данные `text/plain`.
- `normalizePastedTitle` меняет лишь вставленный фрагмент: `\r\n` и `\r` приводятся к `\n`, переводы строк становятся пробелом, серии `\s` схлопываются в один пробел. Края фрагмента и уже набранный текст не нормализуются. Двойные пробелы, набранные вручную, остаются до правки пользователем.
- Фрагмент подставляется вместо выделения и обрезается `clampTitleLength` (`slice(0, TITLE_MAX_LENGTH)`).
- Пустая отправка по-прежнему даёт `Task can't be empty`.

Хранилище:

- `loadTasks(): LoadTasksResult` возвращает `{ tasks, available, discarded }`. `saveTasks(): SaveResult` возвращает `"ok" | "quota" | "unavailable"` и не бросает исключение.
- Сначала `getItem` ключа `tickd:tasks` и разбор, затем проба записи в тот же ключ. Второго ключа нет. Существующее значение перезаписывается теми же байтами. Если ключа нет, под ним кратко пишется `{ version: 1, tasks: [] }` и ключ удаляется.
- `getItem` бросил исключение → `{ tasks: [], available: false, discarded: false }`.
- Задачи прочитаны, проба не прошла → те же `tasks` остаются в состоянии, `available: false`.
- Ключа нет и проба прошла → пустой список, `available: true`, `discarded: false`.
- JSON или схема не прошли, проба прошла → `{ tasks: [], available: true, discarded: true }`. Повреждённые байты лежат до первого успешного сохранения.
- Квота: имя `QuotaExceededError` у `DOMException` или `Error`, либо числовой `code` `22` или `1014`. Остальные исключения записи — `"unavailable"`.
- `makeStore()` без аргумента вызывает `loadTasks()` один раз и кладёт задачи и `persistence` в `preloadedState`. Переданный `preloadedState` в хранилище не ходит.
- Listener (ADR 0002) при `!persistence.available` не вызывает `saveTasks`: сбой, уже увиденный на загрузке, не превращается в `"quota"` на первом изменении. Успешная запись вызывает `clearSaveError()`. Иначе — `reportSaveError`.

Баннер `StorageBanner` — первый ребёнок колонки `max-w-[44rem]` в `App`, над `Outlet`, на каждом фильтре. Сообщение одно. Порядок: `saveError`, затем `loadDiscarded`, затем `!available`, пока баннер недоступности не закрыт.

- Квота (`role="alert"`, `text-danger`): `Can't save tasks — browser storage is full.`
- Сбой записи, хранилище недоступно (`role="alert"`, `text-danger`): `Can't save tasks — browser storage is unavailable.`
- Список отброшен при загрузке (`role="status"`): `Couldn't restore saved tasks. Starting fresh.`
- Недоступность уже на загрузке (`role="status"`, тот же текст про unavailable). Закрытие ставит `availabilityDismissed`. Флаг `available: false` остаётся, и listener по-прежнему не пишет.
- Кнопка закрытия: `aria-label="Dismiss"`. Снимается только текущее сообщение (`saveError → null` или `loadDiscarded → false`).

CSP и разметка:

- Политика в `index.html`:

```html
<meta
  http-equiv="Content-Security-Policy"
  content="default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self' ws: wss:; base-uri 'self'; form-action 'self'; object-src 'none'"
/>
```

- `script-src 'self'` не содержит `unsafe-inline` и `unsafe-eval`. Скрипт приложения — внешний модуль.
- `style-src` включает `'unsafe-inline'`: `vite dev` вставляет CSS (`src/index.css`, `@import "tailwindcss"`) элементом `<style>`. Сборка отдаёт стили через `<link rel="stylesheet">`. Одна политика обслуживает dev, `vite preview` и Pages.
- `connect-src` добавляет схемы `ws:` и `wss:` для websocket HMR Vite.
- `frame-ancestors` в meta нет. Директива в политике из `<meta>` браузерами игнорируется, а Chrome пишет из-за неё ошибку в консоль.
- В `biome.json` правило `security/noDangerouslySetInnerHtml` установлено в `"error"` (группа `security`). В `TaskItem` заголовок — текстовый ребёнок `{task.title}`.

## Рассмотренные альтернативы

- **Только мягкий лимит в интерфейсе.** Счётчик без отказа в reducer и схеме не держит инвариант: поле обходится, а уже сохранённая длинная строка остаётся валидной.
- **Второй ключ пробы (`tickd:__probe`).** Новый ключ на заполненном хранилище может быть отвергнут, пока перезапись того же размера ещё проходит. Отброшенные из-за этого задачи затрёт ближайшее успешное более короткое сохранение.
- **Только HTTP-заголовок CSP.** На GitHub Pages заголовки ответа недоступны. Рабочий канал — `<meta>`.
- **Поэлементное восстановление повреждённого хранилища.** Отклонено в ADR 0003. Лимит длины правило не меняет: одна задача длиннее 200 после `trim` отбрасывает весь список.
- **`innerHTML` / `dangerouslySetInnerHTML` для заголовка.** Текст из хранилища стал бы разметкой. Текстовый узел React и запрет Biome этого не допускают.

## Последствия

- Плюс: поле, вставка, reducer и Valibot сходятся на 200 кодовых единицах UTF-16.
- Плюс: прочитанные задачи остаются, если проба записи не прошла. Квота, недоступность и отброшенный список видны разными сообщениями.
- Плюс: заголовок не разбирается как HTML; запрет закреплён линтером.
- Минус: эмодзи вне BMP и составные последовательности расходуют лимит быстрее, чем число глифов. Счётчик показывает единицы UTF-16.
- Минус: загрузка пишет в `tickd:tasks`. Это уточняет формулировку ADR 0003 «чтение ничего не записывает»: существующие байты проба не меняет, пустой ключ лишь кратко создаётся и удаляется, повреждённые данные по-прежнему не чинятся до реального изменения.
- Минус: закрытие баннера недоступного хранилища запись не включает. Правки сессии остаются в памяти.
- Минус: `'unsafe-inline'` шире, чем нужно собранной странице с одним `<link>`. `ws:` и `wss:` без хоста разрешают websocket на любой origin. `frame-ancestors` через `<meta>` не задать, поэтому встраивание документа в чужой фрейм этой политикой не запрещено.
- Минус: заголовок длиннее 200, записанный до появления лимита, при следующей загрузке отбрасывает весь список.

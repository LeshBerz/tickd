# 0009. Запасной документ для глубоких ссылок на GitHub Pages

- Статус: Принято
- Дата: 2026-11-06

## Контекст

- Фильтр и карточка задачи — это маршруты (`/`, `/active`, `/completed`,
  `/<фильтр>/tasks/:id`), см. [ADR 0001](0001-filter-as-route.md). Ссылки должны
  открываться при холодном заходе.
- GitHub Pages раздаёт статику без перезаписей URL: запрос `/<repo>/active` не находит файл
  и отвечает 404 ([ADR 0004](0004-routing-on-github-pages.md)).
- ADR 0004 предполагал `public/404.html` со скриптом, который кодирует путь в query-строку,
  плюс **inline**-скрипт в `index.html` для восстановления адреса через
  `history.replaceState`.
- CSP в `index.html` содержит `script-src 'self'` без `unsafe-inline`
  ([ADR 0007](0007-input-validation-and-security.md)). Inline-скрипт восстановления адреса
  этой политикой запрещён, а разрешать `unsafe-inline` ради него — ослаблять защиту всей
  страницы.
- Отдельный `404.html` со скриптом редиректа тоже потребовал бы знать базовый путь
  репозитория. Сборка получает его из `BASE_PATH`, но статический файл в `public/`
  не проходит через подстановки Vite, поэтому имя репозитория пришлось бы либо зашить
  в файл, либо генерировать на этапе развёртывания.

## Решение

- На этапе развёртывания workflow копирует собранный `dist/index.html` в `dist/404.html`.
- Никакого редиректа и восстановления адреса нет: GitHub Pages отдаёт `404.html`, браузер
  загружает приложение по исходному URL, а `createBrowserRouter` с `basename` из
  `BASE_URL` сразу разбирает `location.pathname` и рисует нужный экран.
- Ссылки на ассеты в собранном `index.html` абсолютные (`/<repo>/assets/...`), поэтому
  документ работает из любого пути внутри подпути проекта.
- `public/404.html` в репозитории не нужен: файл создаётся только в артефакте.

## Рассмотренные альтернативы

- **Вариант из ADR 0004 (query-строка + `history.replaceState`).** Даёт «чистый» адрес
  после одного лишнего редиректа, но требует inline-скрипта, запрещённого CSP, и знания
  базового пути в статическом файле. Отклонён; ADR 0004 в этой части считается уточнённым
  этим документом.
- **HashRouter.** Работает без запасного документа, но адреса становятся вида
  `/#/active`, что противоречит идее «фильтр — это маршрут» (ADR 0001).
- **Разрешить `unsafe-inline` в `script-src`.** Открывает путь XSS через инъекцию скрипта
  и обесценивает CSP, которая как раз и нужна из-за того, что заголовки ответа на Pages
  недоступны.
- **Другой хостинг с перезаписями.** Решает задачу полностью, но добавляет внешний сервис;
  для этого проекта важно держать код и развёртывание в одном месте.
- **Генерировать `404.html` в `public/` со знанием имени репозитория.** Дублирует источник
  базового пути и ломает локальный `vite preview`, где имя репозитория не участвует.

## Последствия

- Плюс: глубокие ссылки открывают нужный экран без редиректа, вспышки и inline-скриптов.
- Плюс: CSP остаётся строгой, а базовый путь по-прежнему задаётся одной переменной.
- Плюс: нет статического файла, который нужно синхронизировать с `index.html`.
- Минус: ответ на глубокую ссылку имеет HTTP-статус 404. Для клиентского приложения
  без требований к SEO это приемлемо; поисковые роботы такие адреса индексировать
  не будут.
- Минус: поведение зависит от того, что Pages отдаёт `404.html` для любого неизвестного
  пути. Это документированное поведение сервиса, но не гарантия: при смене хостинга
  запасной документ придётся настраивать заново.
- Минус: `index.html` и `404.html` — две копии одного документа, поэтому кэш браузера
  может получить их в разных версиях после деплоя. Обе копии ссылаются на одни и те же
  хэшированные ассеты, поэтому расхождение ограничивается разметкой-оболочкой.
